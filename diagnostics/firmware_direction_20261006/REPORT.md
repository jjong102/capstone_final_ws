# 새 MD200T 방향 설정 진단 및 최초 값 복구

2026-10-06 17:47 KST, 작업 폴더 `/home/moonshot/capstone_final_ws`.

사용자의 최신 지시: 주행 코드는 절대 변경하지 않고 모터드라이버 설정에서 원인을 확인한다.

## 이번 변경과 확인

- **PID52만 1 → 3으로 복구했다.** 3은 임의로 고른 값이 아니라 새 드라이버에서 기준값 이식 전 직접 읽은 값이다. PID79=3(모터 타입)을 적용한 직후에도 PID52=3이었다.
- PID52를 3으로 쓰고 세 번 연속 `03` 응답을 받았다. 검증 중 다른 방향 설정 PID16=0, PID22=0, PID64=1, PID80=0은 그대로였다. 모터 타입=3, 최대RPM=400 및 비교한 나머지 설정도 유지되었다.
- 주행 소스 `test_node_main.py`, `motor_driver.py`의 작업 전후 SHA256이 같다. 설치된 두 파일도 소스와 일치한다. 이전 턴에서 바꾼 w_gain=20과 회전의 버튼 gain 제거는 이번에 수정하거나 되돌리지 않았다.
- 설정 변경 전에 두 채널의 측정 속도와 목표 속도 모두 0을 확인했다. PID10/CMD67로 정지 후 변경했다. 변경 직후에도 속도/목표 속도/구동 출력 모두 0이었다.
- 여기서 비영 속도·위치 명령을 보내거나 ROS 주행 노드를 실행하지 않았다. 마지막 상태는 전기 브레이크 정지(제어 모드 5)다. 사용자에게 바퀴를 띄운 상태에서 드라이버 전원을 재인가한 뒤 기존 실행 방법으로 조이스틱 방향을 확인하도록 요청했다.
- 펌웨어 바이너리를 교체한 작업이 아니라 드라이버의 설정값을 복구한 작업이다.

## 원인 해석의 범위

기존 기준 장치는 MD200T-V7.2e-H100-E, 새 장치는 MD200T-V7.55-H100-E다.

보고된 네 방향(전진→우회전, 후진→좌회전, 좌회전→후진, 우회전→전진)은 오른쪽/모터2의 실제 진행 방향이 논리 명령과 반대일 때의 결과와 일치한다. 그 상태에서는 코드의 직진 계수 100과 속도 버튼 gain이 실제 회전에, 회전 계수 20이 실제 전후진에 나타난다. 이는 증상과 기존 코드로부터의 추론이며 바퀴 방향을 직접 관찰한 결과는 아니다.

PID52는 제조사 통신 문서에서 속도신호 반전 설정으로 설명된다. 새로운 MDT 계열에서는 적어도 PID16에 모터1/2가 BIT0/1로 묶이는 방식이 문서화되어 있지만, V7.55 PID52의 비트 의미를 직접 명시한 자료까지는 확보하지 못했다. 따라서 PID52=3이 반드시 문제를 해결한다고 단정하지 않고, 실제 새 장치에서 확인됐던 최초 값으로 한 항목만 복구하여 사용자 동작 확인을 기다린다. PID16/22를 추가로 바꾸는 보상 설정은 하지 않았다.

## 기준값에서 미응답한 항목

188개 기준 항목 전체를 다시 조회했다. 이전 이식 때와 동일한 19개 항목이 무응답이다: 18, 23, 29, 68, 72, 73, 74, 108, 111, 113, 115, 116, 117, 119, 121, 123, 136, 161, 179.

무응답만으로 값이 누락됐거나 0이라고 판단할 수 없다. 숫자만 있는 구형 별칭과 정의가 불확실한 항목을 쓰지 않았다. 비교한 방향·속도·가감속·모터 타입·제어 gain 등 기존 적용 대상 설정값들은 복구 직전 기준값과 일치했다. 버전, 알람 이력, 입력/제어 상태, 위치, 시간 및 프리셋 조회의 차이는 별도 기록했으며 기준값으로 덮어쓰지 않았다.
